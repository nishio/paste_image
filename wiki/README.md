# wiki

このリポジトリの LLM Wiki。[Karpathy の LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)
の形式に倣い、LLM が読み書きできる Markdown のナレッジベースとして運用する。

これは**プロジェクト目的の Wiki** であり、研究目的の Wiki ではない。
抽象的に整合したネットワークを作るのが目的ではなく、
**この repo を作る作業から得た具体的な知識を filing back する**のが目的。

## ここに書くもの / 書かないもの

| 書く | 書かない |
|---|---|
| 判断の理由、トレードオフ、却下した選択肢 | コードを読めば分かること |
| 詰まった点と、その回避方法 | 実装の手順の逐語的な記録 |
| 外部の制約(プラットフォームの上限、仕様の罠) | 変更履歴(git が持っている) |
| 次に同じ問題に当たった時に読み返したいこと | 一度きりの作業ログ |

仕様そのものは [DESIGN.md](../DESIGN.md)、使い方は [README.md](../README.md) にある。
wiki はそれらと重複せず、**なぜそうしたか**と**作業で分かったこと**を持つ。

## 3つの操作

### Ingest

新しいソース(作業セッション、記事、外部の議論)を取り込む。

1. 生のソースを残す価値があれば `raw/` に置く
2. 既存ページを読み、**新規作成より既存ページの更新を優先する**
3. 1つのソースが複数ページに影響するのが普通。単発の要約ではなく既存ネットワークへの編み込み
4. [index.md](index.md) と [log.md](log.md) を更新する

### Query

wiki に対する質問。関連ページを検索・統合して出典付きで答える。
**良い回答は新しいページとして wiki に filing back する** — チャット履歴に埋もれさせない。

### Lint

定期的な健全性チェック。

- 機械的: `./lint.sh` で検出する(孤立ページ、壊れた `[[リンク]]`、index.md に未登録のページ)
- 意味的: ページ間の矛盾、古くなった記述(Phase が進んで前提が変わる)、概念ページの不足

## 記法

- ページは `pages/<kebab-case>.md`。1ページ1概念
- ページ間リンクは `[[ファイル名(拡張子なし)]]`
- 先頭に `# タイトル` と、その下に1行要約を置く
- 日付は絶対日付で書く(「先週」と書かない)
